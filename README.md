# ReportStudio

多源数据 → 图表 + 结论报告。图片 / PDF / Excel / 文本丢进去，勾选或一句话说清要什么图，出一份带交互图表的 HTML 报告，可另存 Word / PDF。

代码、依赖、产物全部落在**项目自己所在的目录**下，不往系统盘写东西，代码里也没有任何写死的盘符 —— 项目拷到哪个盘都能直接跑。

## 启动

双击 **`启动.bat`** 即可，浏览器会自动打开 http://127.0.0.1:8765 。关掉黑窗口就停止服务。
（8765 被占用时会自动顺延到 8766 / 8767…，并按实际端口打开浏览器，不用手改配置。）

新机器上第一次运行**不需要提前做任何准备**：`启动.bat` 会自己建好虚拟环境、联网装依赖（约 100MB，几分钟），装完直接启动。

等价的命令行：

```
python -m venv .venv
.venv\Scripts\python.exe app.py
```

## 发给别人用

有两种东西可以分享，用途不同。**三条路线的完整对比、各自的工作量与代价，见 [`docs/分享与部署.md`](docs/分享与部署.md)。**

### 一、把工具本身给出去

把整个项目目录打包发出去，或者推到 Git 仓库让对方 clone。对方要做三件事：

1. 电脑上装 **Python 3.10 或更高版本**（Windows 上安装时记得勾选 `Add Python to PATH`）
2. 双击 **`启动.bat`** —— 首次会自动建环境、联网装依赖，等几分钟
3. 浏览器自动打开 http://127.0.0.1:8765 ，之后的用法和你这边完全一样

产物落在**对方自己项目目录下的 `outputs/`**，不会碰到你的机器。对方也不需要你机器上的任何东西。

想先拿假数据试一遍功能，跑这一行就会有：`.venv\Scripts\python.exe samples\make_samples.py`
（`samples/` 里的示例数据都是这个脚本生成的，所以仓库里不放它们 —— 保持纯文本、体积小。）

⚠️ 发出去之前记得**别把这几样带上**：`outputs/`（你的历史报告）、`session/`（你导入的原始数据）、`dashboards/`（你的看板）、`db_connections.json`（数据库地址和**明文密码**）、`.venv/`（依赖，对方会自己装）。

这些都已经写进 `.gitignore`。走 Git 不会误传；如果是**直接拷文件夹**给别人，那就得手动把上面几个目录剔掉。

### 二、把某份报告给出去

单份报告不需要对方装任何东西。`outputs/<报告名>/report.html` 这个文件**是自包含的** —— ECharts 已经整个内嵌进 HTML，不依赖任何 CDN，对方双击就能看，**断网也能看**，图表照样能交互。

一个目录三样东西，按需给：

| 文件 | 用途 |
|---|---|
| `report.html` | 带交互图表的报告，双击即看，单文件可直接发 |
| `report.md` | 纯文本版，方便贴进别的系统或做二次编辑 |
| `charts/` | 每张图的 PNG，写 PPT 或贴微信时用 |


## 出了问题怎么自己看

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 点「生成报告」弹 **「生成出错」** 或页面提示连不上服务 | 服务没在跑（黑窗口被关了 / 根本没启动） | 双击 `启动.bat`，**保持黑窗口开着**，然后刷新页面 |
| 黑窗口提示「端口 8765 被占用，已自动改用 8766」 | 上一次的服务没关干净 | 直接用即可，浏览器已按新端口打开。想用回 8765，把上次那个黑窗口关掉再启动 |
| 弹「服务端出错（XXX）」 | 后端真遇到异常 | 完整堆栈写在项目目录下的 `logs\error.log`，看一眼最后一段就知道哪炸了 |
| 磁盘占得比预期多 | 删报告 / 看板时文件被占用，删不掉就改名成 `.deleted` 留着 | 页面底部「历史报告」右上角有「清理缓存」按钮（有东西可回收时才出现），点一下即可 |
| 历史报告列表里找不到某份报告 | 搜索框里有残留的关键词 | 清空搜索框。列表默认只显示最近 50 份，搜索是走服务端的，搜得到全量 |
| 报告里图少了 / 数字对不上 | 见下面的「会静默算错的坑」，解析提示都写在导入后的预览区 | 按提示改列类型或表头行号 |
| 连数据库报「缺少驱动」/ 连接超时 | 驱动没装齐，或网络/端口不通 | 双击 `安装依赖.bat` 补装；SQL Server 还要单独装 ODBC 驱动。连接失败的原因会翻译成中文写在面板上 |
| SQL 被拒「只允许查数」 | 触发了只读闸门（写了 INSERT/UPDATE 等） | 这是设计如此。要改数据请用别的工具，这个工具只取数 |
| 导出报「这份报告已过期」 | 报告目录在服务重启前生成的内存注册表里找不到了 | 重新点一次「生成报告」再导出；`outputs\` 里的 `report.html` / `report.md` 一直都在，不受影响 |
| 打开看板少了几张图 | 看板依赖会话里的数据表，那些表被清理了 | 看板顶部会**列出**具体是哪几张表没找到。把数据重新导入（或重新连库取数）后再点「打开」即可 |

页面加载不出来时也能自检：浏览器打开 http://127.0.0.1:8765/api/status ，
能看到一串 JSON 就说明服务是活的。

## 界面流程

```
1 导入数据   拖拽 / 点选 / 粘贴表格 / 指定文件夹批量导入
2 从数据库取数  选库类型 → 填连接 → 列表 → 写 SQL（只读），结果同样落进会话
3 数据预览   改表头行号、改列类型（数值/日期/文本），看解析提示
             → 改完可点「导出这张表」存成 CSV / Excel，把修正结果带走
             （CSV 带 BOM，Excel 双击打开中文不乱码）
4 多文件整合 自动判断哪些表结构相同可合并，可手动改
             勾选「剔除合计/总计/小计行」（默认开）
5 说清需求   一句话描述，或直接勾选图表类型 / 横轴 / 数值 / 聚合 / 排序
             每张图里**每个指标可以各选各的图型**（柱状 / 折线 / 面积 / 堆叠柱 /
             饼图 / 散点图），不再是所有指标共用一个图型
             勾两个以上指标时可选「多指标」：合并成一张图 / 拆成多张单指标图
             两个以上数列且图型合适时可勾「双轴」，第二个走右轴
             报告版面可选「每行 1 / 2 / 3 张」
             每张图可选「看板宽度」（半宽 / 整宽 / 三分之一 / 四分之一）
6 数据看板   把上面配好的图 + 指标存成一屏看板，随时点开看最新数据
   → 生成报告 + 导出 Markdown / Word / PDF / 总图 PNG
```

底部预览区是**「报告 / 看板」两个视图，点一下就切换**，不用生成两次：

- 点「生成报告」→ 报告这一屏就地刷新。
- 切到「看板」→ **按当前配置和当前数据实时重算**再显示。改了图表、换了数据、
  重新导入了表，切过来看到的就是最新的，不需要再去点一次「保存到看板」。
- 想长期留着这份看板，再到第 6 块点「保存到看板」。
- 预览框右边的**「放大预览」**会把整块预览区铺满浏览器窗口（再点一次或按 ESC 退出）。
  屏幕小的时候看板挤成一团，这个按钮比来回滚页面省事。

看板里每张图右上角还有「放大」——铺满一屏看这一张，并且**能看它背后的数据表、导出 CSV**。
详见下面的「数据看板」一节。

报告里每张图右上角有「保存为 PNG」，点了直接下载 2 倍分辨率的白底图，
方便手动贴进 PPT。打印时这些按钮会自动隐藏。

页面底部是「历史报告」，列出 outputs 里所有报告：**可按名字搜索**、直接打开、
补导出 Word / PDF、以及**逐份删除**。每行显示这份报告有几张图 / 几个指标 / 多少行 /
占多大，一眼能认出是哪一份（报告攒到几百份时这一点很关键）。

同一行的右端还有「清理缓存」：删报告或看板时如果文件被占用没删干净，后端会把文件改名成
`.deleted` 兜底，这些残片没有任何流程会再读，只会占地方。按钮会如实显示
「清理缓存（163 个 · 80 MB）」，点一下回收 —— **正常报告、看板配置、数据表都不在回收范围内**。
服务每次启动也会自动回收一次。

## 多图 / 合并 / 拼总图

### 每个指标可以各选各的图型

一张图表卡里勾了「销售额、毛利率」，不用再拆成两张卡分开配 ——
在「数值」下面，**每个已选指标各占一行**，单独选它的图型：

- `销售额` → 柱状图、`毛利率` → 折线图：**合并在同一张图里**，柱子打底、折线叠上去看率
- 想让所有指标都用同一种图型，就改卡片顶上的「类型」，底下保持「跟随默认」

有两类图一张图只装得下一个指标，选中后**会自动单独成图**，不用手动拆：

| 图型 | 为什么必须单独成图 |
|---|---|
| 饼图 | 一张图就一个圆环，塞第二个指标没有对应的扇形 |
| 散点图 | 横轴得是数值列（看两个数值的关系），和柱状/折线的分类横轴不是一回事 |

界面上会当场写明「会单独成图」，不会出现「改了却像没反应」。

### 多指标：合并还是拆开

四个不同层次的选择，都在界面上，互不干扰：
| **报告版面每行几张** | 「说清需求」里的「图表版面」 | 想要一屏看全就选每行 2~3 张；要单张大图就保持每行 1 张 |
| **拼成一张总图** | 预览区「导出总图」 | 逐张存太碎，发给人要发一堆文件。拼成一张长图/网格图，一次转发 |

拆图的两条细节：

- 拆开后每张图标题会带上指标名（你自定义了标题也照样带），否则三张同名分不清哪张是哪个。
- **排序依据会跟着走**：你说「按资产报酬率降序」再拆成三张图，三张图的横轴顺序保持一致
  （都按资产报酬率排）。否则两张图顺序不一致，读者会误以为两个指标的趋势对不上。

拼图只做一件事：把 matplotlib 已经画好的 PNG 拼起来，不重新绘图。
重新绘图会让「网页上看到的图」和「拼出来的图」可能不一致，而用户会当成同一个东西。

## 支持什么输入

| 类型 | 扩展名 | 说明 |
|---|---|---|
| 表格 | xlsx / xlsm / xls / csv / tsv | 多 sheet 逐个导入；GBK、分号/竖线分隔自动识别；合并单元格前向填充 |
| 文档 | docx / txt / md | 抽内嵌表格，再从「指标：值」这类行里抽键值对 |
| PDF | pdf | 文本型直接抽表；扫描件自动改走视觉模型 |
| 图片 | png / jpg / webp / bmp | **需要配置大模型才能识别**，见下 |
| 粘贴 | — | Markdown 表格优先；否则 Tab / 多空格 / 逗号 / 竖线自动分列 |

导入的表会**落盘到 `session\`**，关掉服务再打开还在，不用重新传。
5 万行以上的表只放内存，7 天前的文件自动清理。`config.yaml` 里 `session.persist: false` 可关掉。
界面上有「清空所有数据」，会连磁盘缓存一起清。

## 从数据库取数（SQL，只读）

除了丢文件，也可以直接连库写 SQL 取数，取回来的结果和导入的表格**完全一样**地走后面的出图链路。

支持的库：

| 类型 | 你需要的 | 说明 |
|---|---|---|
| SQLite | 无 | 填 `.db / .sqlite / .db3` 文件路径，或点「上传库文件」；示例库在 `samples\demo_shop.db` |
| MySQL / MariaDB | `pymysql` | 端口默认 3306 |
| PostgreSQL | `pg8000` | 端口默认 5432；`database` 填库名 |
| SQL Server | `pyodbc` + 本机装「ODBC Driver for SQL Server」 | 端口默认 1433，驱动名可不填自动挑 |
| Oracle | `oracledb` | 端口默认 1521；`service` 填**服务名**（如 `ORCLPDB1`），不是 SID |

驱动都在 `安装依赖.bat` 里装好了；SQLite 用的是 Python 自带的，不用装。

**五步**：选库类型 → 填连接（可「保存连接」下次直接选）→「连上并列表」→ 点表名自动生成
`SELECT` 模板 → 改 SQL → 「取数并出图」。

### 只读是硬约束，不是开关

写在 `config.yaml` 里当注释也只是备注——实际是**三重闸门**，任何一层拦住都执行不了：

1. **语句闸门**（`core/db/guard.py`）：只放行 `SELECT` / `WITH` 开头的单条语句。
   校验前先把注释、字符串字面量、引号标识符**遮蔽**掉再扫关键词，所以
   `SELECT 'DROP TABLE'` 不会被误杀，而 `DR/**/OP TABLE` 这种拆词绕过也躲不掉。
   同时拒绝多语句（`SELECT 1; DROP TABLE t`）和可写 CTE（`WITH x AS (DELETE … RETURNING *)`）。
2. **连接闸门**：SQLite 用 `mode=ro` 打开；网络库连接后立刻 `SET … READ ONLY`
   （Oracle 是 `SET TRANSACTION READ ONLY`）。**就算语句闸门被绕过，这一层也会直接报
   `attempt to write a readonly database`。**（SQL Server 没有会话级只读，靠第 1 层。）
3. **资源闸门**：语句超时（默认 30s）+ 行数上限（默认 20000 行，超了截断并在报告里写明）。

改 `config.yaml` 的 `database.max_rows` / `timeout_ms` 可调后两项；前两层没有开关。

**建议**：给这个工具单独开一个只有 `SELECT` 权限的数据库账号。三重闸门是兜底，不是让你拿生产管理员账号来连的理由。

### 密码与安全

- 连接配置存在项目目录下的 `db_connections.json`（已写进 `.gitignore`，不进版本库）。
- **密码不会回显**：任何接口返回的连接信息里只有 `has_password: true/false`，明文只在你自己填的那一刻存在于请求里。
- 密码是**明文存盘**的（本地单机工具，够用）。默认「记住密码」开着；不想存就取消勾选，或在 `config.yaml` 里关掉 `database.remember_password`。
- 不勾「记住密码」时，密码只在当前这次配置里有效，下次要重填。

取数结果会带上来源提示写进报告：「数据来源：MySQL 10.0.0.5:3306/dw」这类，
被截断时也会写明「只取回前 N 行」——**报告里的数字是不是完整的，一眼能看出来**。

## 数据看板

报告是**长文档**（往下滚着读、打印成册）；看板是**一屏**——指标卡一行 + 图表按网格平铺，
打开就看完，适合挂屏幕上或汇报时截图。

两者是**同一块预览区的两个视图**（底部「报告 / 看板」切换），数据来源和图表配置完全共用：

- 切到「看板」会**按当前配置和当前数据实时重算**，所以你改了图、换了数据，
  切过去看到的一定是最新的 —— 不用先保存、也不用再点一次生成。
- 每次都重算而不是缓存，是因为「明明刷新了却没变」最难查：用户会以为数据没更新，
  实际是拿了旧结果。
- 想长期留着这份看板，再到第 6 块起个名字点「保存到看板」。之后在下方列表点「打开」，
  会**按当前数据重新渲染**再打开。

**存的是「怎么算」，不是数字。** 看板里保存的是「要哪几个指标、哪几张图、怎么排」，
所以数据更新之后，同一个看板点开就是新数据 —— 它是镜子不是快照。
反过来说：**它依赖会话里的数据表**。如果那些表被清理了（重启没恢复、手动删了、7 天到期的缓存），
看板会照常打开，但会**明确在页面顶部列出哪几张表没找到、哪些图被跳过了，并告诉你怎么恢复** ——
不会安静地少几张图让你以为「这个指标本来就没数」。

| 能力 | 说明 |
|---|---|
| 布局 | 12 栅格网格，每张图可选半宽 / 整宽 / 三分之一 / 四分之一；窄屏自动变整宽 |
| 指标卡 | 勾了「指标列」就按勾的来；不勾就按表里的数值列自动出（列表里显示「指标按列自动」） |
| **放大看单张** | 每张图右上角「放大」→ 铺满一屏的大图 + **数据表**两个视图，还能「存 PNG」「导出 CSV」 |
| 全屏 / 打印 | 右上角「全屏」；「打印 / 存 PDF」会按横向铺满打印，按钮自动隐藏 |
| 单图导出 | 每张图右上角「存 PNG」，2 倍分辨率白底图，直接贴 PPT |
| 存盘位置 | 配置 `dashboards/<id>.json`，渲染结果 `dashboards/<id>.html`（都在 E 盘） |
| 访问地址 | http://127.0.0.1:8765/dashboards/&lt;id&gt;.html ，刷新即重算 |

### 放大某一张图，看它背后的数

看板是一屏概览，图上挤是常态 —— 20 个省市的饼图，标签会叠成一团。
所以每张图右上角有**「放大」**：

- **图表视图**：铺满整个面板的大图。类目多于 12 个时**默认只显示前 12 个**，
  底下多一条缩放条，拖着看其余部分 —— 全塞进来的话标签还是叠着，那就白放大了。
  散点图给的是横纵两个方向的缩放条。
- **数据表视图**：这张图背后的数据，一行一个类目、一列一个系列，可上下滚动。
- **导出 CSV**：带 UTF-8 BOM —— 不带的话 Excel 双击打开中文全是乱码。
- 关掉的方式：点「关闭」、点面板外的暗色区域、按 ESC。

表里的数是从**这张图的配置反解出来的**，不是另算一遍 —— 所以它必然和图上看到的一致。
这一点是有意的：百分比列在画图时乘过 100（0.15 画成 15%），另算一遍就会出现
「图上是 15%、表里写 0.15」，用户不知道该信哪个。

> 预览区的框只有 640px 高，放大面板在这么矮的地方铺不开。
> 所以预览区右上角还有个**「放大预览」**：把整个预览框铺满浏览器窗口，再点一次或按 ESC 退出。
> （想更宽敞就直接点「新窗口打开」。）

看板用和报告同一套浅色商务配色，所以看板截图贴进 Word 不会突兀。

## 关于大模型（可选）


> 受限环境里一次跑太多套会撞上「批量删除保护」（每个套件收尾都要删自己建的表）。
> 撞上了就分成两三批跑，不影响任何断言。
> `history_export` 因此**排在靠前**的位置：它要验证删除行为，而守卫是按
> 「一个 turn 内删满 50 个文件」算额度的，排到后面会被前面的套件把额度用光。
> 那套里有一个探针会识别这种情况并跳过删除断言，不让环境限制变成假红。

| 套件 | 管什么 |
|---|---|
| `smoke` | 全流程冒烟：6 类文件导入 → 出图 → 四种格式导出 |
| `compat` | 危险列名、7 张异构表分章节、图片降级混合 |
| `type_matrix` | 八种来源单测 + 全场景矩阵（没图片/没表格/空输入/坏 id/空文件/非法图型） |
| `missing_value` / `category_missing` | 缺失值占位符、分类列为空 |
| `merge_conflict` | 合并时同名列类型冲突 |
| `history_export` | 历史报告的搜索 / 删除 / 越权防护、数据表导出 CSV+xlsx（含 BOM）、残片回收、异常处理器唯一性 |
| `recoverable_numeric` | 脏数值格式（全角/中文量级/货币/百分号） |
| `dup_columns` | 重名列改名的连环撞名 |
| `sort_semantics` | 排序：被点名的指标不被抢去当横轴、降序词表、报告里落地顺序真是降的 |
| `pie_negative` | 饼图遇负值：matplotlib 不崩、ECharts 不静默画错图、摘要里写明换了图型、其它图型不受影响 |
| `multi_chart` | 多图/合并/版面/拼总图/看板即时预览；含「拆图后排序仍生效」与 12 组畸形输入 |
| `db_readonly` | 数据库取数：闸门、绕过尝试、取数出图、密码不回显、畸形输入 |
| `dashboard` | 看板：保存、按当前数据重算（不是快照）、缺表提示、改名、删除、**放大看单张图与它的数据表**（含 `</script>` 注入防护）、畸形输入 |
| `check_frontend` | DOM id/class 引用与后端字段的静态对齐 |
| `frontend_logic` | 用 jsdom 真跑前端逻辑（60 项断言） |
| `no500` | 接口 fuzz：任何输入都不许 5xx |

所有套件都只清理自己建的表，**不会动你在界面上存着的会话数据**。

`check_frontend.py` 做的是 `node --check` 抓不到的事：把 `app.js` 里引用的每个
DOM id / class 和 `index.html` 里的真实元素对一遍，再抽查 JS 读的字段后端是否真的返回了。
纯手写 DOM 的项目最容易在这上面翻车——引用一个不存在的 id，整个界面直接瘫痪。

`frontend_logic.js` 更进一步：把 `app.js` 丢进 jsdom **真跑**，断言排序下拉项、转义行为、
拆图开关的显隐、报告/看板切换有没有真去请求预览 —— 这些「静态检查看不出来、
只有运行时才暴露」的逻辑。这个项目里已经靠它抓到四个只在运行时才报的 bug：
`ctype` 拼错导致排序选项整段不生成、预置排序被覆盖掉、勾选数列时不刷新排序下拉、
以及拆图开关在只剩一个指标时没收回（残留上次的「拆开」设置）。

**写测试的一个教训**（踩了三次，记下来）：`sort_semantics` / `multi_chart` 第一版各有
几项「失败」，查完发现全是**断言自己写错了** —— 比如「取销售额前 5」的第 5 名是北京不是四川、
用 `sorted()` 比中文标题（按 Unicode 码点排，`利润 < 毛利率 < 销售额`）。
所以断言里比中文顺序一律用 `set`，比数值前先把预期手算一遍，
别让假失败把注意力从真正的 bug 上带走。

## 会静默算错的坑（都处理了）

这些不会报错，只会给出「看着挺合理其实是错的」的数字，是最危险的：

| 坑 | 错误结果 | 现在的处理 |
|---|---|---|
| **百分比列求和** | 毛利率「合计 4.60」 | 列名含率/占比且值在 0~1.5 → 判为百分比列，出均值 |
| **标记列求和** | 「985 合计 2785」「江苏 321 所双一流」 | 值只有 0/1/2 的标记列 → 数「1」的条数，标题注明口径 |
| **时间维度字符串排序** | `1月 2月 … 12月` 排成 `10月 11月 12月 1月 2月` | 自然排序：切成文字块/数字块，数字按数值比 |
| **缺失值占位符误判** | 列里混着 `N/A`、`-`、`—`、`/`、空单元格，整列被误判成文本、出不了图 | 统一识别缺失占位符（`N/A`/`-`/`—`/`/`/`无`/`空`/`暂无`/`null`…）并排除出列类型推断的分母，列仍判为数值；这些格变成缺失值而非 0 或字符串 |
| **分类列为空凭空多一根柱** | 分类列（省份/月份…）有空单元格/缺失，被当成「空」分组，图上多出一根聚合出来的幽灵柱 | 聚合时剔除分类为空的行并计数，结论里提示「有 N 行因『列名』为空未计入图表」；整列皆空时不出图、不崩 |
| **同名列静默覆盖** | 一张表里两列都叫「金额」，行的数据按列名做键 → 后一列覆盖前一列，值凭空少一个、图和指标全错，且列数看着没少 | 重名列自动改名（`金额` / `金额_1`），**改名后继续查重**（否则 `金额_2 / 金额 / 金额` 会改出第二个 `金额_2` 照样撞名），保证列名唯一、值一个不丢 |
| **被点名的指标被抢去当横轴** | 说「按资产报酬率降序」，出来的图横轴是资产报酬率、数值却换成了另一个指标，图上一次都看不到你要的那个数 | 找横轴时**只在文本列里找**，找不到就用第一个文本列兜底，**绝不占用被点名的指标**（散点图例外，它本来就该是两个数值列）。降序词表也补齐了「从高到低 / 由大到小 / 从多到少」这些说法 |
| **饼图里混进负值** | 导出 Word/PDF 直接崩（`Wedge sizes 'x' must be non negative values`）；更糟的是**网页上那张饼图不报错但占比是错的** —— 负值不参与圆周分配，图上看着只有正数那几块，数字全错还没人知道 | 聚合层统一决策：饼图数据含负值就**自动改用柱状图**（负值在柱状图上往下伸，数据一个不丢），并在报告摘要里点名是哪几个分类为负、说清为什么换图型。取绝对值、剔掉负值行都是在替用户改数字，占比会跟着失真，所以不动数字只动图型 |
| **拆图后排序静默失效** | 说「按资产报酬率降序」再拆成三张单指标图，只有第一张真的排了序，另外两张的排序键不在自己的系列里 → 保持原序、看着像没排。三张图顺序不一致，读者会以为两个指标趋势对不上 | 排序键允许指向**没被画出来的列**（先在行层面把该列聚合出来当排序依据）。这同时也解决了「按销售额排序、但只画利润」这种正常需求 |

另外「用文字代替 1」的脏数据也能救：`双一流` 列填「双一流」而非数字时，
若数字部分是 0/1、或只有 1/2 编码且该词恰好等于列名，就按 1 处理，并在报告里写明。
缺失占位符同样不参与这个判断，所以混了 `N/A` 的标志列也能照常识别。

## 输入兼容性与转义（不崩是底线）

不管有没有图片、不管文件多脏，报告都要能出出来：

- **所有来自文件的文本都会转义**：列名叫「部门`<script>`」、含 `&`、`|`、引号的内容，
  进入 HTML / PDF（XML）和 Markdown（管道符撑破表格）前一律做转义，页面不会被搞坏。
- **图片不一定有，也不一定要有**：没配大模型时，图片/扫描件返回「需配置接口」的提示并降级为空表，
  **不会阻塞其他表出图**——Excel、文本、PDF 照常生成报告。
- **没有可出图的数据 ≠ 出不了报告**：只有纯文本、只有扫描图片、或表里根本没有数值列时，
  以前会直接报错（「至少配一张图」/「没有算出可绘制的数据」），现在改为**降级输出一份「数据摘要报告」**
  （结论 + 指标卡 + 数据明细照旧），并在报告开头写明为什么没有图。配了图但横轴/数值列对不上时同样降级，不再整份失败。
  `POST /api/generate` 会返回 `degraded: true` 与说明文字 `note`。
- **多种类型可混着导**：Excel + 文本 + PDF + 粘贴 一次丢进去，同构自动合并、异构各成章节。
- **合并时同名列类型冲突会自动调和**：两张表都有「金额」，一张因混了脏单元格被误判成文本、
  另一张是数字，合并后列按「数字 > 日期 > 文本」取更精确的类型，并把值按目标类型规整
  （文本数字 `"100"` → `100`、不可解析的变 `None`），同时报告里提示哪些列类型不一致。
  否则数字会被当成文本、整列出不了图、数据静默丢失。
- 端到端兼容性测试见 `tests/compat.py`（危险列名 / 7 张异构表分章节 / 图片降级混合）
  与 `tests/type_matrix.py`（八种来源单测 + 「没有图片 / 没有表格 / 空输入 / 坏 id / 空文件 / 非法图型」全场景矩阵）。
- **脏数值格式也能识别成数字**：全角数字（３５６）、中文量级单位（1.2万 / 3亿 / 5千）、
  Unicode 减号（−123）、货币符号+千分位（¥1,234,567）、百分号（12.5%）都能正确转成数值列。
  但「数字里夹非数字文字」如「约1.2万」「（亏损）」会**如实判为文本**，不强行猜。

### 一个无法自动解决的语义边界（需人工确认）

数值清洗救得了「格式脏」，救不了「单位乱」：列名叫「销售额(万元)」、单元格却填「3亿」时，
解析器只能按字面把 3亿 当成 300000000，没法判断作者本意是「3亿元」还是「3万万元」。
这类单位混淆属于原始数据问题，请在预览阶段核对列单位。

### 百分比列在图表里显示成 `%`

毛利率、同比增长这类列底层存的是小数（0.125 = 12.5%），聚合、排序、指标卡都按小数算（正确）。
但画图时如果直接显示 `12.5%` 之外的形态会误导人，所以：
- 轴标题标注「列名 (%)」，刻度/数据统一 ×100（看到的是 `12.5` 而不是 `0.125`），ECharts 轴标签再补 `%`；
- Word / PDF 的静态图用 matplotlib 的 `FuncFormatter` 走同一套逻辑，两边一致。


## 几个已知的取舍

- **HTML 用 ECharts 交互图，Word / PDF 用 matplotlib 静态图**。这样导出不依赖本机装 Node 或浏览器。同一张图有两套渲染代码，风格尽量对齐了。
- **报告 HTML 自包含**：1 MB 的 ECharts 源码内联进去了，所以单文件拷给别人双击就能看，缺点是文件偏大。
- **导入的表会落盘到 `session\`**，关掉服务再打开还在，不用重新传（见上「会话持久化」）。5 万行以上的表只放内存、7 天前的缓存自动清；`config.yaml` 里 `session.persist: false` 可关。
- **上传的临时文件不会立刻删除**，攒在 `temp\` 里，下次启动时清掉 24 小时以前的（每次最多 15 个）。
  这么改是因为解析完立刻 `os.remove` 会撞上某些环境的批量删除保护，直接把请求线程打死——
  踩过一次，服务在上传时崩了。清理逻辑在 `app.cleanup_temp()`，失败也不影响启动。
