# 多源数据图表报告工具 — 方案设计

> 状态：**已按此方案实现并通过端到端冒烟测试**（2026-09-22）。
> 项目目录可以放在任意盘、任意路径，代码、依赖、产物都跟着项目目录走。

## 一、它干什么

把图片 / PDF / Excel / 文本丢进去 → 抽成统一的数据表 → 你用一句话或表单说清要什么图 → 出一份带交互式图表和关键结论的 HTML 报告，可另存 Word / PDF。

## 三、数据流转（8 步）

```
① 摄入   文件/拖拽/粘贴/文件夹 → ingest.py 按类型分发
                ↓
② 解析   各 parser 输出统一 Dataset（带解析告警，如"第3列17个非数字已置空"）
                ↓
③ 预览   界面上可改：表头行、列类型、哪些列参与分析    ← 容错的关键一步
                ↓
④ 整合   merge.py 判定同构/异构 → 合并成大表 或 分章节
                ↓
⑤ 需求   一句话 → spec.py → Spec JSON（也可纯表单直出，结果同样写回表单）
                ↓
⑥ 计算   analyze.py 聚合/排序/算指标   ← 所有数字在这里产生，大模型不碰
                ↓
⑦ 渲染   echarts.py 出交互图 + html_report.py 套模板
                ↓
⑧ 导出   HTML（主） / Markdown / Word / PDF
```

## 四、两个核心数据结构

**Dataset** —— 所有输入最终都长这样：

```python
@dataclass
class Column:
    name: str
    dtype: str            # "number" | "date" | "text"
    unit: str | None      # 如 "万元"

@dataclass
class Dataset:
    id: str
    name: str             # 来源文件名
    source_type: str      # excel / pdf / image / text / paste
    columns: list[Column]
    rows: list[dict]
    raw_text: str         # 原文摘录，报告末尾溯源用
    warnings: list[str]   # 解析告警，界面和报告里都展示
```

**Spec** —— 你的需求最终长这样（自然语言和表单两条路都汇到这）：

```json
{
  "title": "各月销售额分析",
  "template": "full",
  "charts": [
    {
      "type": "bar",
      "x": "月份",
      "y": ["销售额"],
      "agg": "sum",
      "sort": {"by": "销售额", "order": "desc"},
      "filter": [],
      "dual_axis": false
    }
  ],
  "metrics": ["销售额", "订单量"],
  "limit": null
}
```

图表类型初始支持：`bar` 柱状 / `line` 折线 / `pie` 饼环 / `scatter` 散点 / `stack_bar` 堆叠柱 / `combo` 柱线双轴组合。
排序支持：按某列升/降、按时间先后、自定义顺序。

## 五、容错设计（你选了"尽量容错"，这是重点）

1. **表头自动探测**：扫描前 15 行，按四个信号打分——非空比例、值是否唯一、下一行数据类型是否一致、是否含"合计/小计/总计"字样。得分最高的行当表头。界面上一键改。
2. **列类型推断**：某列 >80% 的值能转成数字才算数值列，否则降级为文本列，避免把"订单号"当数字求和。
3. **合并单元格**：openpyxl 前向填充，标题行/单位行自动识别为元数据而非数据。
4. **同构判定**：列名集合重合度 ≥70% 且列类型一致 → 判为同构，合并时自动加一列"来源文件"；否则各自独立成章节。
5. **粘贴分列**：先按 Tab 切，不行按 2 个以上空格切，再不行按逗号切；只有一列就当纯文本处理。
6. **数字安全**：所有展示的数字由 `analyze.py` 计算产出，大模型只拿到"已算好的数字"做文字润色，prompt 里明确禁止改动任何数值。

## 六、大模型的三个接入点（可全关）

| 编号 | 作用 | 没配 key 时的降级行为 |
|---|---|---|
| V1 | 图片 / 扫描版 PDF → 结构化 JSON | 提示"此文件需配置大模型接口"，其余文件照常处理 |
| V2 | 自然语言一句话 → Spec JSON | 降级为纯表单勾选 |
| V3 | 数字 + 上下文 → 分析段落润色 | 降级为模板化描述句（"销售额合计 XX，环比 +X%"） |

接口层按 OpenAI 兼容协议写，`config.yaml` 里填 `base_url` / `api_key` / `model` 就能换厂商，DeepSeek、通义、GLM、本地 Ollama 都能接。

## 九、Word / PDF 里的图表怎么来 —— 已选定方案 A

ECharts 是网页图表，没法直接塞进 Word 和 PDF。备选三方案：

| 方案 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| **A. 双引擎（已选）** | HTML 用 ECharts 交互图；Word/PDF 用 matplotlib 重画一份静态图 | 零额外依赖、绝对稳定、断网可用 | 同一张图要维护两套渲染代码，风格需手动对齐 |
| B. 服务端渲染 ECharts | 装 Node，用 ECharts SSR 出 SVG/PNG 插进 Word/PDF | 图表风格与网页版完全一致 | 多一个 Node 依赖 |
| C. 调用 Chrome 无头打印 | 用本机 Chrome/Edge 把 HTML 报告打印成 PDF | PDF 与网页版像素级一致 | 依赖本机装了 Chrome/Edge；Word 导出仍要另想办法 |

选 A 的理由：稳、不挑环境，而且汇报场景里放进 Word 的图本来就是静态的。
实现在 `core/render/static_chart.py`，由 `analyze.aggregate` 的同一份结果喂进去，数字不会两处打架。

### 过程中修掉的四个真问题

1. **改表头行坐标系错位**：原先只保留解析结果、丢掉了原始网格，用户看到的「第 3 行」其实对不上原始文件。改为保留原始网格。
2. **自然语言说「按月」匹配不上列名「月份」**：加了逐级放宽的别名匹配（去后缀 → 取主干），并兜底到保证能出图。
3. **百分比列被求和**：毛利率算出「合计 4.60」这种废话。现在列名含「率/占比」且值落在 0~1 之间即判为百分比列，改出均值。
4. **多张雷同图导致摘要重复同一句话**：结论文案去重。
