## 二、三条路，怎么选

### 路线 A · 可分享运行包（改动最小）

**做法**：把项目目录压成 zip 发出去，或推到 Git 仓库让对方 `clone`。

| 项 | 内容 |
|---|---|
| 对方要准备什么 | 装 **Python 3.10+**（Windows 安装时勾选 `Add Python to PATH`） |
| 对方拿到后做什么 | 解压 → 双击 `启动.bat` → 首次联网装依赖（几分钟）→ 浏览器打开 `127.0.0.1:8765` |
| 功能完整度 | **和你现在完全一致**（导本地文件、连数据库、看板、导出全都在） |
| 还差什么 | 一个打包脚本：压 zip 时排除 `outputs/ temp/ .venv/ session/ dashboards/ db_connections.json` |
| 成本 | **小** |

这是最省事也最实用的一条。绝大多数「发给同学/同事用」的场景，这条就够了。

### 路线 B · 免安装 exe（改动中等）

**做法**：用 PyInstaller 打成单个可执行文件，对方双击即用、什么都不用装。

| 项 | 内容 |
|---|---|
| 对方要准备什么 | 无 |
| 功能完整度 | 完整 |
| 还差什么 | 打包配置 + 反复试错（matplotlib / pandas 的隐藏依赖容易漏） |
| 代价 | 体积 **300~500MB**，首次启动稍慢，杀毒软件可能误报需手动放行 |
| 成本 | **中**（主要成本在试错，不在写代码） |

### 路线 C · 在线链接（改动最大）

**做法**：部署到一台公网服务器，别人打开网址就能用、零安装。

| 项 | 内容 |
|---|---|
| 对方要准备什么 | 无（浏览器） |
| 功能完整度 | **有真实损失，见下** |
| 还差什么 | 服务器环境（或 Dockerfile）、域名/端口、HTTPS、多用户数据隔离 |
| 成本 | **大** |

**如实说明代价，别抱错预期：**

| 功能 | 在线版会怎样 |
|---|---|
| 导入本地文件 | ✅ **可用**。因为本来就是浏览器上传，文件会传到服务器上再解析（注意：数据因此落在服务器） |
| 导入文件夹 | ✅ 可用（`webkitdirectory` 上传） |
| **数据库取数** | ⚠️ **基本失效**。取数是从**服务器**发起连接，你填 `127.0.0.1:3306` 指的是服务器自己。只有当数据库本身能从公网访问时才用得了 |
| 报告 / 看板 / 导出 | ✅ 可用 |
| 多人同时用 | ⚠️ 当前是单实例共享会话，多人会互相看到彼此导入的数据，**必须加隔离才能对外开放** |
| 密钥 | 在服务器上写 `config.local.yaml`（不进仓库） |

### 走不通的一条：GitHub Pages

Pages 只能托管**静态文件**，而这个工具是 FastAPI 后端 + Python 计算，跑不起来。
它顶多能放一个「样例报告展示页」，用来给人看效果，不能给人用工具。

## 二·补、视觉模型接口（图片 / PDF 结构化识别）怎么共享

图片、扫描版 PDF 的结构化表格识别，依赖一个**支持 vision 的大模型接口**。这一节专门回答：
**「我配好了接口，把工具发给别人，对方也要自己配吗？」**

**结论：默认要，而且应该要。** 原因在于 `config.local.yaml` 在 `.gitignore` 里，
你的 API key **根本不会进分享包**。所以无论是 zip 还是 Git 仓库，对方拿到的都是
「没有 key 的干净模板」，必须自己填。这是有意为之：

- **安全**：key 一旦进包，等于把你的密钥发给别人；
- **费用**：不隔离的话，别人用它识别图片的账单全算在你头上；
- **兼容**：别人的模型厂商 / 模型名大概率和你不同。

但这个「要自己配」已经做到**最轻量**，二选一即可：

| 对方怎么做 | 操作 | 说明 |
|---|---|---|
| 设环境变量（推荐，不改文件） | 重启服务前设 `RS_LLM_BASE_URL` / `RS_LLM_API_KEY` / `RS_LLM_MODEL` | 一行都不用编辑，特别适合在线部署（路线 C） |
| 写本地配置 | 在 `config.local.yaml` 的 `llm` 段填 base_url / api_key / model | 和你的用法完全一致 |

**不配 key 也能用吗？能。** 视觉接口没配时，图片识别会**自动回落到本地 OCR**
（前提是那台机器装了 tesseract）——至少能把图片里的文字抽成文本，只是分不出表格结构。
真正的「图片→结构化数据表」才需要 vision key。换句话说：**分享出去的包开箱即可做文字级提取，
配上各自的 key 后升级为表格级识别。**

如果你确实需要「别人拿去就直接能用你的接口」（不推荐，除非你愿意承担安全与费用），
唯一的办法是把 key 写进**公开**的 `config.yaml`——但那样密钥会随包发出去，强烈不建议。
更稳妥的替代：给对方开一个**受限的只读子账号 / 代理地址**，让他填到自己的 `config.local.yaml`。

> 视觉模型可以和对话模型分开：在 `llm` 段加 `vision_model: 模型名` 即可，
> 留空则和 `model` 相同。多数账号对话与视觉是不同模型名，分开指定更准。

## 三、分享前的自检清单

不管走哪条路，**发出去之前确认这几样不在包里**（直接拷文件夹时尤其要注意，走 Git 有 `.gitignore` 兜底）：

| 不能带的东西 | 里面是什么 |
|---|---|
| `db_connections.json` | 数据库地址、用户名、**明文密码** |
| `outputs/` | 你的历史报告与图表，含真实业务数据 |
| `session/`、`session_trash/` | 你导入的原始数据表 |
| `dashboards/` | 你的常驻看板配置 |
| `.venv/` | 依赖，对方会自己装（约 300MB） |
| `config.local.yaml` | 你的 API key |
| `dashboards/*.deleted`、`*.tmp` | 删除没删干净留下的残片，没有任何流程会再读它，纯占体积 |

> **打包前先在「历史报告」右上角点一次「清理缓存」。** 那个按钮只在真有东西可回收时才出现，
> 会如实显示规模（本机实测曾到 163 个 / 80 MB）。点完再打包，省下的都是纯垃圾。
> 服务每次启动也会自动回收一遍，所以放着不管也不会无限涨。

**一条命令自检**（在项目目录下执行，输出应为空）：

```bash
git status --porcelain | grep -E "db_connections|\.venv|session/|dashboards/|outputs/|\.local\.yaml"
```

## 四、单份报告怎么分享

不需要对方装任何东西，也不依赖这个工具：

- `outputs/<报告名>/report.html` —— **自包含**，双击即看，断网也行，图表能交互
- `report.md` —— 纯文本版，方便贴进别的系统
- `charts/*.png` —— 每张图的静态图，写 PPT 或发微信时用

只发 `report.html` 一个文件就够了。

## 五、本机环境备注（这些在 E 盘，不随项目走）

按「数据一律放 E 盘」的约定，SSH / Git 相关文件都已迁到 E 盘，C 盘只留入口链接：

| 内容 | 位置 | C 盘入口 |
|---|---|---|
| SSH 密钥（`id_ed25519` / `known_hosts`） | `E:\ssh\` | `C:\Users\张原\.ssh` 是指向它的 **junction** |
| Git 全局配置 | `E:\git\.gitconfig` | 由用户环境变量 `GIT_CONFIG_GLOBAL` 指过去 |

回滚方法（如需改回默认位置）：

```cmd
:: 撤掉 git 配置重定向
setx GIT_CONFIG_GLOBAL ""
:: ~/.ssh 若要恢复成实体目录：删掉 junction 再把 E:\ssh 拷回来
```

> 注：跨盘**符号链接**在这台机器上不可靠（实测创建出的是空文件），
> 所以 `~/.ssh` 用的是 junction，单文件（`.gitconfig`）用的是环境变量重定向。
